# 03. Integration Architecture

## Принцип

Компоненты не вызывают друг друга как библиотеки. Взаимодействие — три соглашения:
**файлы** (данные проекта и записи работы), **команда** (argv → json + код возврата), **идентификатор**
(всё, на что можно сослаться, имеет стабильный id). Это даёт запуск из коробки, из CI, из редактора и с
другой машины без переписывания.

## Поверхность команд (минимум)

| Команда | Что делает | Кто зовёт |
|---|---|---|
| `pantheon new <путь>` | создаёт коробку, пишет `box.toml`, compose, профиль | человек |
| `pantheon up` / `down` | поднимает и гасит контейнер Августа | человек |
| `pantheon status` | состояние из реестра: задачи, попытки, вердикты, открытые вопросы | человек, Август |
| `pantheon task new` | задача как файл: цель, объём, критерий готовности, бюджет | Август, человек |
| `pantheon run <task>` | Caesar: проверка контракта, попытка, артефакты, запись события | Август |
| `pantheon verify <change>` | Trajan: план проверок, прогон, вердикт, артефакты | Август, человек, CI |
| `pantheon arch check` | Aurelius: модель против кода, нарушения | Август, Trajan |
| `pantheon arch propose` | черновик модели по репозиторию (нужен человек для принятия) | человек |
| `pantheon ledger tail` | что произошло, по событиям реестра | человек, Август |
| `pantheon resume <box> --task <id>` | продолжает прерванную задачу с её артефактов; без `--retry` модель не зовёт | человек, Август |
| `pantheon outbox flush` | сводка наружу | Август |

Все команды печатают json при `--json`, код возврата означает результат, а не настроение: 0 — сделано,
1 — отказ по правилу, 2 — ошибка исполнения.

## Поток сквозного сценария

1. Человек ставит задачу текстом. Август пишет `tasks/<id>.toml`: цель, объявленный объём (пути, тип:
   docs/bugfix/feature/architecture/security), критерий готовности, бюджет.
2. Август по таблице (объём → контуры) решает, нужен ли Aurelius, и зовёт `pantheon arch check` или
   получает выдержку ограничений из модели.
3. Август зовёт `pantheon run`: Caesar валидирует контракт (пути, инструменты, лимиты, разрешения),
   запускает исполнителя, пишет попытку и артефакты.
4. Август зовёт `pantheon verify`: Trajan строит план по путям и политике, гоняет проверки, вызывает
   ревью, считает вердикт кодом, пишет отчёт и событие.
5. Август читает вердикт и обновляет проекцию: задача закрыта или возвращена с находками; при `HOLD`
   повторная попытка — только с новой записью и новым бюджетом.
6. `pantheon outbox flush` пишет сводку для личного Hermes.

Шаги 2–4 — разные команды, поэтому любой из них можно запустить вручную: это и есть проверка
независимости компонентов.

## Продолжение прерванной задачи

Задача может остановиться на середине: исполнителя убили, машина перезагрузилась, кончился бюджет.
`pantheon dispatch` кладёт рядом с артефактами снимок задачи (`artifacts/<id>/task.json`) и копию
объявленного патча, поэтому продолжение не требует ни исходного файла задачи, ни памяти о том, что
происходило. `pantheon resume <коробка> --task <id>` читает снимок и артефакты и продолжает с того места,
где остановилось:

| Что осталось на диске | Что делает `resume` |
|---|---|
| ворота применили изменение, записи о проверке нет | проверяет то дерево, которое изменили ворота |
| предложение записано, ворот не было | проводит записанный патч через ворота и проверку |
| вызов стоил дороже бюджета | отказывается применять, пока лимит не поднят: `--max-cents` берёт уже оплаченный вызов, а не платит второй раз |
| исполнитель не ответил | без `--retry` отказывается: продолжать нечем, поэтому сначала новый вызов |

Чего `resume` не делает: не просит модель заново о том изменении, которое уже лежит на диске; не
проверяет дерево, в котором применённого изменения уже нет (и не закрывает такую задачу); не
пересчитывает вердикт, который уже посчитан — закрытая задача продолжению не подлежит. Событие
`task.resumed` и строка `resumed from` в записи и в outbox говорят, откуда продолжили.

## Повтор проверок

Проверка на неизменившемся дереве не гоняется второй раз. Перед прогоном коробка считает
отпечаток: содержимое рабочего дерева проекта (коммит, диф к нему и содержимое неотслеживаемых
файлов), файл политики и исходники самого Траяна. Рядом с каждым прогоном она пишет
`box-verify.json` — на чём вердикт держался и какой отчёт он собой закрыл.

Если отпечаток совпал с прошлым прогоном, `verify` не запускает проверки: ответ берётся из того
отчёта, а новая запись и вывод команды говорят `reused` и откуда именно. Что переиспользуется и
что нет:

| Случай | Что происходит |
|---|---|
| `pass` или `pass_with_conditions`, дерево и политика те же | повтор: тот же отчёт, новая запись со ссылкой на старую |
| `hold` | прогон заново: если человек смотрит снова, он обычно что-то починил |
| `inconclusive` | прогон заново: вердикт не решён, а причина могла быть в среде |
| изменилось дерево, файл политики или исходники Траяна | прогон заново |
| прошлому прогону больше суток | прогон заново: время не входит в отпечаток |

Что отпечаток не покрывает и что поэтому сказано вслух: файлы под `.gitignore` (проверка,
читающая их, может ответить иначе на том же отпечатке), версии интерпретатора и установленных
инструментов. Отсюда окно в сутки и обязательная строка `reused from` в записи, outbox и выводе
`verify`: повтор — это утверждение «входы те же», а не «проверки прошли ещё раз».

## Чего прогон не проверил

Слово «closed» в записи отвечает только за то, что было посчитано. Поэтому каждая запись, outbox
и `status` называют пробелы явно, разделом «what we did not check»:

- вердикт получен прогоном **только проверок** — изменение никто не читал, и про его смысл вердикт
  ничего не говорит;
- вердикт **переиспользован**: проверки сейчас не гонялись, это ответ про то же дерево, посчитанный
  раньше;
- архитектура **не подтверждена** (`unchecked`), потому что нет модели или нет инструмента;
- проверка **не маршрутизирована** или не оставила результата;
- исполнитель **не сообщил расход** — бюджет проверить нечем;
- задача **не объявила бюджет** — прогон ничем не ограничен.

Пустой список печатается как `- none`: «ничего не осталось» — это утверждение, которое тоже надо
увидеть, а не догадаться о нём по отсутствию строки.

## Как ограничен Август

Профиль коробки (ACL Hermes) выдаёт ему:
- чтение проекта и файлов коробки;
- `pantheon` CLI как инструмент;
- запись **только** через CLI-команды, которые сами пишут реестр;
- отсутствие родного shell, редактора и произвольной записи файлов.

Проверка этого — тест: попытка Августа записать файл вне контракта должна быть отклонена окружением, а не
уговариванием. Если ограничение держится только инструкцией в `SOUL.md`, оно не существует.

## Форматы

- Задача и контракт — TOML: читаются человеком, диффятся, не требуют библиотеки.
- Артефакты прогона — каталог с `report.json` и `report.md` (формат trajan): вердикт машинно читаемый,
  человеку — рендер.
- Реестр — `ledger/<дата>.jsonl`: одна строка — одно событие со ссылками на артефакты. Дописывается,
  не переписывается.
- Схемы данных версионируются (`schema_version`), и компонент обязан отказаться читать чужую версию,
  а не угадывать.

## Деградация

| Что отсутствует | Что всё ещё работает |
|---|---|
| Август (контейнер не поднят) | `pantheon verify`, `arch check`, `status` по реестру — вручную |
| Aurelius (нет модели) | Trajan проверяет по политике; архитектурная проверка помечается «не выполнялась» |
| Caesar (нет контракта) | `verify` работает по изменению в рабочем дереве; запись попытки помечается ручной |
| Trajan (нет политики) | `run` исполняет, но результат помечается «не проверено», вердикта нет |
| личный Hermes | ничего не меняется: коробка от него не зависит |

Правило: отсутствие компонента — это видимое состояние (`not_applicable`, «не выполнялось»), а не тихий
пропуск.

## Связь с личным Hermes

Только `outbox/`: одна сводка на закрытую задачу — что сделано, какой вердикт, какие решения приняты,
что осталось. Личный Hermes читает и накапливает свой контекст. Обратный поток отсутствует: коробка не
запрашивает у ассистента память и не зависит от его доступности. Позже можно добавить сводку по всем
коробкам, но это задача ассистента, а не Пантеона.
