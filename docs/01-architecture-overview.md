# 01. Architecture Overview

## Три уровня

```
┌──────────────────────────────────────────────────────────────┐
│ личный Hermes (снаружи, одна штука) — контекст о работе вообще│
└───────────────┬──────────────────────────────────────────────┘
                │ читает только outbox, односторонне
┌───────────────▼───────────────┐   ┌───────────────────────────┐
│ коробка проекта A             │   │ коробка проекта B         │
│  Augustus (Hermes, свой том)  │   │  Augustus (Hermes, свой)  │
│  Aurelius · Caesar · Trajan   │   │  Aurelius · Caesar …      │
│  реестр, артефакты, outbox    │   │  реестр, артефакты, outbox│
└───────────────┬───────────────┘   └───────────────┬───────────┘
                │ монтируется                       │
        ┌───────▼────────┐                  ┌───────▼────────┐
        │ репозиторий A  │                  │ репозиторий B  │
        │ политика, модель│                  │ …              │
        │ требования, ADR│                  │                │
        └────────────────┘                  └────────────────┘
```

**Уровень 1 — правда о проекте, в репозитории.** То, что должно пережить коробку, ревьюиться вместе с
кодом и переезжать в другую машину: политика проверок, требования и инварианты, архитектурная модель,
ADR. Это файлы; их правит человек; коробка их читает и не переписывает (кроме предложений — отдельным
каталогом и с подписью).

**Уровень 2 — записи работы, в коробке.** Задачи, контракты исполнения, попытки, прогоны, вердикты,
события, артефакты, outbox. Это история, и она принадлежит коробке, а не проекту: клон репозитория без
коробки — проект без истории, коробка без проекта — история без объекта.

**Уровень 3 — контуры.** Aurelius, Caesar, Trajan — независимые инструменты со своим входом и выходом.
Август их не «вызывает внутри себя», а передаёт задачу и собирает результат.

## Анатомия коробки

```
~/pantheon/boxes/<project>/
├── box.toml            # имя, путь к репозиторию, тег образа, бюджеты, лимиты
├── compose.yaml        # один сервис: augustus; тома и монтирование проекта
├── profile/            # чей образ Августа: SOUL.md, ACL инструментов, модель
├── state/              # том Августа (/opt/data): сессии, его память, кэш
├── ledger/             # события работы: jsonl по дням + указатель
├── artifacts/          # каталоги прогонов: report.json/md, логи проверок
├── tasks/              # задачи и контракты исполнения (данные, не треды)
└── outbox/             # сводки наружу для личного Hermes
```

`pantheon new <путь>` создаёт каталог и файлы, `pantheon up` поднимает контейнер, `pantheon down`
гасит, `pantheon status` показывает состояние из реестра, не спрашивая Августа.

## Что где живёт и почему

| Что | Где | Почему там |
|---|---|---|
| Политика, требования, архитектурная модель, ADR | репозиторий проекта | ревьюится с кодом, переносится с проектом, диффится |
| Задача, контракт, попытка, прогон, вердикт, событие | коробка | это запись работы, а не обещание проекта |
| Личность, привычки, память Августа | `state/` коробки | принадлежит экземпляру, а не проекту |
| Ключи и токены | окружение хоста/секрет-хранилище | в каталог коробки и в git не попадают |
| Сводки для личного Hermes | `outbox/` | односторонний поток; коробка не зависит от ассистента |

## Ресурсы и эксплуатация (по факту)

- Один контейнер Hermes занимает около 423 МБ; на машине 11 ГБ памяти, из них ~7 ГБ доступно. Две-три
  живые коробки влезают спокойно, остальные поднимаются по требованию.
- Образ фиксируется по тегу в `box.toml`; `latest` запрещён. Иначе обновление снесёт все коробки разом,
  и воспроизводимость, которую мы собираемся доказывать, исчезнет.
- Коробка переезжает как каталог: `tar` каталога и `pantheon up` на другой машине. Путь к репозиторию в
  `box.toml` — единственное, что может потребовать правки.
- Коробка не запускает собственных сетевых сервисов в MVP. Август говорит с контурами через CLI и
  файлы; наружу — только outbox.

## Что в коробке отсутствует сознательно

- Личный Hermes и его память. Иначе контекст проектов и контекст твоей работы смешаются, и ни один из
  двух не будет верным.
- Собственный оркестратор-код. Оркестрация — это планирование в голове Августа плюс данные задач.
- Собственная база данных. Реестр — jsonl-файлы; поиск по ним — `grep` и маленький индекс, пока объём
  не потребует обратного.
- Собственный agent runtime. Он берётся у Hermes, а его версии фиксируются.

## Открытый вопрос

«Настоящая коробка» — контейнер, в который проект кладут внутрь, — обсуждается отдельно и позже. Пока
проект монтируется, а коробка живёт рядом: этого достаточно, чтобы ходить по сценарию и не придумывать
перенос проектов раньше, чем есть что переносить.
