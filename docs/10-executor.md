# 10. Исполнитель: команда, которая производит изменение

Изменение производит **объявленная команда** — исполнитель: задача на stdin, патч и счёт на stdout.
Его исполнение бывает разным, и harness этого не различает: DeepSeek по API, `claude -p` по подписке,
ваш собственный скрипт или — с 2026-11-24 — агент коробки внутри контейнера
(`bin/pantheon-executor-container`). Во всех случаях остальное одно: патч проходит через ворота
Caesar, проверку запускает Trajan, запись ведёт Augustus.

Смысл в том, что harness не знает, кто именно ответил: он знает только формат ответа и что с
ответом делать.

## Что объявляет коробка

Файл `persona/executor.toml` в коробке:

```toml
schema_version = 1
command = "/home/ubuntu/pantheon/bin/pantheon-executor"
model = "deepseek-flash"   # необязательно: имя по умолчанию
max_seconds = 300
max_cents = 5

# Модель по виду задачи: ключ — `kind` из файла задачи. Тариф (долларов за миллион
# токенов) объявляет коробка, иначе цена второго вида считалась бы по чужому прайсу.
[models.docs]
model = "deepseek-chat"
price_in = 0.15
price_out = 0.60
```

Нет файла — нет исполнителя: задача тогда должна нести свой патч, и запись так и говорит.

Бюджет задачи может **уменьшить** лимиты коробки, но не увеличить: потолок задаёт коробка.

**Модель по виду задачи.** Вид берётся из задачи, а не угадывается по тексту: `[models.<вид>]`
называет модель и, если нужно, её тариф. Выбор делает harness до вызова: есть запись для вида —
она, иначе `model`; выбранная модель уходит в запрос полем `model`, тариф — в окружение команды
(`PANTHEON_MODEL_PRICE_IN`/`PANTHEON_MODEL_PRICE_OUT`), а решение пишется в `proposal.json`
полем `model_choice` и в событие `task.executed` тем же полем. Если тариф не объявлен, окружение
не переопределяется и цена остаётся за командой. Одна половина тарифа без второй — отказ профиля:
половина цены не цена.

`command` — не «модель», а обычная команда. Её можно заменить на любую другую, которая говорит
на этом протоколе.

## Запрос: что команда получает

Задача приходит JSON-объектом на stdin и одновременно лежит в `tabularium/<task>/proposal-<n>/request.json`:

```json
{
  "schema_version": 1,
  "attempt": 1,
  "task": {"id": "t-1", "goal": "…", "kind": "bugfix", "paths": ["src/**"],
           "expected": "…", "forbidden": [], "budget": {"max_cents": 5}},
  "project": {"path": "/home/ubuntu/pantheon/trajan"},
  "box": {"name": "trajan", "root": "/home/ubuntu/pantheon/castra/trajan"},
  "limits": {"max_seconds": 300, "max_cents": 5, "max_read_chars": null},
  "record": {"directory": "/home/ubuntu/pantheon/castra/trajan/tabularium/t-1/proposal-1"},
  "model": "deepseek-flash",
  "context": {"…": "пакет контекста, если коробка его собрала"},
  "previous": null
}
```

`limits.max_read_chars` — потолок чтения на задачу: если задача объявила `max_read_chars` в
`[budget]`, команда обязана не читать больше, а всё, что не влезло, назвать в ответе. `null` —
потолок не объявлен, действует собственный предел команды.

`previous` — не `null` только у повтора: это факты прошлой попытки (вердикт, проваленные проверки,
находки), собранные кодом из записи; исполнитель обязан на них ответить, а не повторить задачу
ещё раз.

Команда запускается в каталоге проекта и вправе проект **читать**.

## Ответ: что команда возвращает

JSON-объект на stdout, ничего больше. Ключи:

| Ключ | Обязателен | Что значит |
|---|---|---|
| `patch` | один из двух | унифицированный диф текстом |
| `patch_file` | один из двух | путь к дифу; относительный считается от `record.directory` |
| `usage` | нет | `prompt_tokens`, `completion_tokens`, `cost_cents` — что потрачено |
| `model` | нет | имя модели, как его назвал поставщик |
| `notes` | нет | список строк, которые попадут в запись |
| `reading` | нет | что команда прочитала: `files`, `chars`, `tokens_estimate`, `cap_chars`, `declared_chars`, `left_out` (список строк) |
| `duration_ms` | нет | сколько заняло по мнению команды |
| `error` | нет | «я не смог»; это записывается как отказ, а не как пустой патч |

Неизвестный ключ — дефект протокола: ответ считается неудачным, а не «почти правильным».
Пустой ответ — тоже неудача: «ничего не вернул» не равно «изменение не нужно».

## Что harness делает с ответом

1. **Ограничивает время.** Не уложилась в `max_seconds` — процесс останавливается, попытка
   записывается как неудачная.
2. **Проверяет, что команда не писала сама.** До и после вызова снимается `git status` и `HEAD`:
   если дерево изменилось, это `unapproved-write` — изменение не применяется, задача возвращается.
   Команда предлагает, а не пишет.
3. **Проверяет цену.** Если ответ говорит про `cost_cents` больше разрешённого — изменение
   записывается, но не применяется (`over-budget`).
4. **Отдаёт патч Caesar.** Тот же контракт, те же ворота, тот же отказ по путям.
5. **Зовёт Trajan** после применения — как и раньше.
6. **Записывает чтение.** Если ответ назвал `reading`, запись, `pantheon dispatch` и `pantheon
   status` печатают, сколько файлов и символов попало в запрос, оценку токенов и что осталось за
   потолком. Не назвала — запись говорит «not reported», а не рисует ноль.

Каждый вызов оставляет каталог `tabularium/<task>/proposal-<n>/`: `request.json`, `stdout.txt`,
`stderr.txt`, `change.diff`, `proposal.json` (со статусом, ценой и токенами).

## Где видна стоимость

Критерий приёмки MVP — «стоимость задачи записана». Она записана в трёх местах:

- **событие** в `fasti/<дата>.jsonl` типа `task.executed` с полями `model`, `prompt_tokens`,
  `completion_tokens`, `cost_cents`, `seconds`;
- **запись** `dispatch-*.json`, блок `executor`, и `proposal.json`;
- **сводка** в `acta/`, раздел `## cost`: деньги, токены, модель, время и бюджет задачи.

Чтение — отдельная строка `reading` в `dispatch-*.json`, в `proposal.json` и в выводе `pantheon
dispatch`: файлы, символы, оценка токенов, объявленный потолок и всё, что осталось за ним. Три
правила записи:

- **Токены не выдумываются.** Не сообщила команда — в записи стоит «tokens not reported», а не 0.
- **Деньги не выдумываются.** Нет цены — «cost not reported» (а не «бесплатно»).
- **Ноль — это число.** «Модели не было» пишется словами, а не нулём в графе стоимости.

## Эталонный адаптер

`bin/pantheon-executor` — минимальная реализация протокола поверх OpenAI-совместимого
endpoint (DeepSeek по умолчанию). Он читает задачу, кладёт в промпт объявленные пути и файлы из
них, просит один диф, вытаскивает его из ответа и печатает JSON с токенами и ценой.

Настройки — только через окружение, ключ в репозиторий не попадает:

| Переменная | Что задаёт |
|---|---|
| `PANTHEON_MODEL_KEY` или `DEEPSEEK_API_KEY` | ключ |
| `PANTHEON_MODEL_URL` | endpoint, по умолчанию `https://api.deepseek.com/chat/completions` |
| `PANTHEON_MODEL` | модель, если профиль её не назвал |
| `PANTHEON_MODEL_MAX_TOKENS` | потолок ответа, по умолчанию 4096 |
| `PANTHEON_MODEL_PRICE_IN`, `PANTHEON_MODEL_PRICE_OUT` | доллары за миллион токенов; без них цена неизвестна |

Цены для `deepseek-flash` в этом проекте уже объявлены в примерах trajan: 0,30 $ за миллион
входных и 1,20 $ за миллион выходных (пиковые, проверено 2026-11-23,
`https://api-docs.deepseek.com/quick_start/pricing`). Те же числа подходят для переменных выше.

Включение в коробке:

```bash
cp ~/pantheon/castra/trajan/persona/executor.toml.example \
   ~/pantheon/castra/trajan/persona/executor.toml
# в файле: command = "/home/ubuntu/pantheon/bin/pantheon-executor"
PANTHEON_MODEL_KEY=… PANTHEON_MODEL=deepseek-flash \
PANTHEON_MODEL_PRICE_IN=0.30 PANTHEON_MODEL_PRICE_OUT=1.20 \
./bin/pantheon dispatch trajan --task mandata/t-2.toml
```

## Исполнитель внутри коробки

У коробки есть свой агент: `pantheon up` запускает `gateway run` в контейнере, профиль
(`persona/SOUL.md`, копируется в `cella/` при первом старте) и модель — часть коробки. Тогда
исполнителем становится `bin/pantheon-executor-container`: он переводит задачу в один промпт,
зовёт `hermes -z` внутри контейнера, забирает диф и **счёт самого агента** (`--usage-file`:
вход, выход, кэш, оценка стоимости). Проект внутри контейнера смонтирован только на чтение,
поэтому агент физически не может писать: он предлагает, а применяет Caesar на машине.

Ключ модели — секрет коробки: `cella/.env`, режим 600, вне git; `up` записывает его из
окружения вызывающего. В compose-файл ключ не попадает (и не может: `sudo` вычищает окружение).

## Границы, названные явно

- **Порт под агента не публикуется**: gateway слушает петлевой адрес внутри контейнера, наружу
  выставлен только `docker exec`/`docker compose exec` — этого хватает исполнителю, но не
  браузеру. Публичный доступ к агенту — отдельное решение.
- **Проверка «не писал сам» — по git.** Проект не под git — предупреждение в записи, а не тихая
  уверенность.
- **Один диф за вызов.** Нет потокового вывода, нет инструментов, нет нескольких попыток внутри
  одного вызова: повтор — это новая задача или новый запуск.
- **Команда доверенная в одном смысле:** ей можно читать проект. Писать — нельзя, и это
  проверяется, а не обещается.
- **CLI под подписку** (`claude -p`, `codex exec`) — отдельный адаптер того же протокола; тогда
  бюджет считается попытками и минутами, а в записи честно стоит «модель не наша, лимиты
  вендора». Решено после MVP, этап 3 дорожной карты.
