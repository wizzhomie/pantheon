# 07. MVP Specification

## Что доказывает MVP

Что коробка работает: проект подключён, задача прошла путь от текста до вердикта, запись сохранилась, а
новая сессия продолжает работу без объяснений. Не «четыре агента запускаются», а **один сквозной
сценарий, повторяемый дважды**.

## Объём

**Входит:**

- `pantheon new <путь>` — коробка для одного проекта: `box.toml`, compose, профиль, пустые ledger и
  artifacts, монтирование репозитория.
- `pantheon up` / `down` / `status` — контейнер Августа и состояние из реестра.
- Задача как файл: цель, объявленный объём (пути + тип), критерий готовности, бюджет.
- Контракт исполнения: разрешённые пути, запрещённые действия, таймаут, бюджет, ожидаемый результат.
- `pantheon run` — один исполнитель, одна попытка, артефакты и событие; отказ при выходе за контракт.
- `pantheon verify` — trajan как есть: план по путям, проверки, ревью, вердикт кодом, отчёт.
- Одна архитектурная проверка: модель из `architecture.toml` против реальных зависимостей проекта.
- Реестр: события, из которых восстанавливается «что сделано, что решено, что открыто».
- Outbox: одна сводка на закрытую задачу.

**Не входит:** несколько коробок одновременно, несколько исполнителей и роли, обновление модели Aurelius
автоматически, интерфейс согласований, сравнение моделей, динамическая глубина проверки сверх таблицы,
«настоящая коробка» с проектом внутри, экспорт архитектуры в нотации.

## Сценарий приёмки (тот самый, который считается)

1. `pantheon new ~/trajan --name trajan-dev` — коробка. В `status` видны проект, политика, требования.
2. Человек пишет: «добавь проверку, что отчёт не ссылается на несуществующий файл». Август формирует
   задачу: объём — `src/trajan/verify/`, `tests/`, тип `feature`, критерий — новый тест зелёный, старые
   зелёные, бюджет — пять центов.
3. Таблица маршрутов говорит: `feature` в `src/` → Aurelius (архитектурные ограничения) + Caesar + Trajan.
4. `pantheon run` — Caesar проверяет контракт, запускает исполнителя, пишет попытку и артефакты. Попытка
   изменить файл вне объявленных путей отклоняется.
5. `pantheon verify` — Trajan выдаёт вердикт; `hold` возвращает задачу с находками, `pass` её закрывает.
6. Август обновляет проекцию и пишет сводку в `outbox/`.
7. `pantheon down`, затем `pantheon up` и `pantheon status` — задача, вердикт и следующий шаг на месте,
   без пересказа проекта человеком.

## Критерии приёмки

| № | Критерий | Как проверяется |
|---|---|---|
| 1 | Коробка создаётся на чистом клоне и поднимается | `pantheon new` + `up` + `status` на копии репозитория |
| 2 | Задача объявляет объём, и без него не стартует | запуск без типа/путей — отказ, код 1 |
| 3 | Запись вне контракта отклоняется окружением, а не уговором | тест: попытка Августа писать в файл вне списка |
| 4 | Вердикт выпускает код, отчёт машинно читается | отчёт по схеме; при `hold` есть причина и доказательство |
| 5 | Состояние переживает перезапуск | `down`/`up`/`status`; задача и вердикт на месте |
| 6 | Повторная проверка того же изменения даёт тот же вердикт | два прогона, сравнение вердиктов |
| 7 | Стоимость задачи записана | событие с токенами и деньгами; бюджет виден в задаче |
| 8 | Отсутствие контура видно | без политики — «не проверено»; без модели — «архитектура не проверялась» |

## Что переиспользуется, а что пишется

| Часть | Откуда |
|---|---|
| Август, планирование, память сессий, инструменты | образ Hermes, профиль коробки |
| Trajan: проверки, ревью, вердикт, отчёт | trajan, без изменений |
| Архитектурная проверка | обёртка над существующим инструментом границ |
| Коробка, контракт, попытка, реестр, outbox | пишем мы; это и есть вклад Пантеона |

## Исполнитель в MVP

Один адаптер: CLI-агент, который правит рабочее дерево в объявленных путях. В тестах вместо живой модели —
записанный ответ (кассета), чтобы проверка не стоила денег и не зависела от сети; живой прогон — отдельно и
с бюджетом в центы.

## Чего в MVP быть не должно

Демонстрационного «агента», который ничего не делает, но красиво выглядит; второго контура проверки;
собственного анализатора; сервисов и брокеров; согласований в интерфейсе; автоматической маршрутизации
через LLM. Всё это либо уже есть, либо ждёт своего этапа.
