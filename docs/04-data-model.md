# 04. Shared Data Model

## Правила

1. **Один владелец на объект.** Владелец — тот, кто создаёт и меняет; остальные читают или получают
   выдержку.
2. **Идентификаторы выводятся, а не выбираются.** Изменение объекта порождает новый id, а не «тот же,
   но другой»; id никогда не переиспользуется.
3. **Каждое утверждение ссылается на доказательство.** Запись без ссылки либо помечена как мнение, либо
   не принимается.
4. **Схемы версионируются.** Компонент отказывается читать чужую версию вместо того, чтобы угадывать.
5. **Файлы в репозитории — правда проекта; записи в коробке — история работы.** Никаких копий между
   ними: только ссылки.

## Сущности

| Объект | Ключевые поля | Владелец | Где живёт |
|---|---|---|---|
| `Box` | имя, путь к репозиторию, тег образа, бюджеты, создана | человек | `box.toml` |
| `Requirement` / `Invariant` | id (`R1`, `I2`), заголовок, статус (`approved`/`proposed`/`superseded`), проверки | проект (файл), проверяет Trajan | `.trajan/context.toml` |
| `ArchModel` | модули, разрешённые зависимости, слои, инварианты, `baseline`/`target` | Aurelius (по решению человека) | `.pantheon/architecture.toml` |
| `ArchViolation` | правило, путь, доказательство, дата | Aurelius | событие реестра |
| `Decision` | `ADR-NNN`, заголовок, статус, альтернативы, последствия | Aurelius | `docs/adr/` в репозитории |
| `Campaign` | id, замысел, рамка, приёмка, бюджет, шаги; отпечаток файла | Augustus | `.pantheon/campaigns/<id>.toml` |
| `Step` | id, цель, вид, роль, пути, ожидаемый результат, зависимости, потолок центов | Август (план) | внутри кампании |
| `Acceptance` | id, формулировка, шаг, чей вердикт её покрывает | владелец и Август | внутри кампании |
| `CampaignState` | какие шаги закрыты, вердикты, стоимость, план-отпечаток | Augustus (пишет), код (читает) | `artifacts/campaign/<id>/state.json` |
| `CampaignVerdict` | `ready` / `in progress` / `incomplete` / `complete` / `over budget`, причины | код | вычисляется из плана и состояния |
| `Task` | `t-<дата>-<слаг>`, цель, объявленный объём (пути + тип), критерий готовности, бюджет | Augustus | `tasks/<id>.toml` |
| `Contract` | task id, разрешённые пути, запрещённые действия, инструменты, таймаут, бюджет, ожидаемый результат, нужно ли одобрение | Caesar | `tasks/<id>.contract.toml` |
| `Attempt` | `<task>/<n>`, исполнитель, старт/финиш, код, стоимость, артефакты | Caesar | `artifacts/<task>/<n>/` |
| `Change` | дайджест диффа, базовый коммит, затронутые пути | Caesar (из попытки) | `artifacts/<task>/<n>/change.json` |
| `VerificationRun` | id прогона, план, проверки, находки, вердикт, дайджесты политики/контекста/модели | Trajan (trajan) | `artifacts/<task>/verify-<id>/` |
| `Finding` | `F1`, статус (`confirmed`/`unverified`/`ambiguous`/`false-positive`), важность, доказательство, требование | Trajan | внутри `report.json` |
| `Verdict` | `pass`/`pass_with_conditions`/`hold`/`inconclusive`, причины | Trajan | внутри `report.json` |
| `Frame` | модель, политика путей и требования как один отпечаток; что отсутствует | код (читает) | `.pantheon/`, `.trajan/context.toml` |
| `Approval` | отпечаток рамки, файлы, кто и зачем принял, базовый коммит | человек | `artifacts/frame/approval-<at>.json` + событие `frame.approved` |
| `RecordDigest` | отпечаток, счёт, записи (задача, вид, вердикт, тронутые пути, адрес), что не вошло | код (пишет), человек читает | `artifacts/records/digest.json` |
| `ContextPack` | рамка с отпечатком, отобранные записи и причины, указатели, бюджет символов, что осталось за бортом | код (пишет), исполнитель читает | `artifacts/<task>/pack-<at>.json` |
| `Budget` | потолок попытки/задачи/коробки, потрачено | Caesar | `box.toml` + события |
| `Event` | `e-<дата>-<номер>`, тип, время, ссылки, действующее лицо | все (пишут), читает Август | `ledger/<дата>.jsonl` |
| `OutboxEntry` | задача, вердикт, решения, открытые вопросы, стоимость | Augustus | `outbox/<дата>-<task>.md` |

## Идентификаторы

| Объект | Формат | Почему так |
|---|---|---|
| коробка | слаг проекта | совпадает с каталогом, переносится без правки |
| задача | `t-20261124-fix-vat-rounding` | дата и смысл видны в реестре без расшифровки |
| попытка | `t-…/2` | номер попытки — часть бюджета и истории |
| прогон проверки | как выдаёт trajan: `<timestamp>-<policy>` | совпадает с уже существующими отчётами |
| событие | `e-20261124-0042` | монотонно внутри дня, склеивается в историю |
| решение | `ADR-012` | номер один раз, переиспользовать нельзя |
| находка | `F1` | уже принято в trajan; требования — `R1` |

## Связи

```
Task 1—1 Contract 1—n Attempt 1—1 Change 1—n VerificationRun 1—n Finding
  │                    │                          │
  └────────── Event ───┴──────── Budget ──────────┘
Decision ── ссылается на Requirement и ArchModel
OutboxEntry ── ссылается на Task, VerificationRun, Decision
```

## Что не хранится

- Треды переписки с агентом. В реестре — задача, контракт, попытка и результат; разговор остаётся в том
  компоненте, который его вёл (у Августа — его сессии), и на него можно сослаться, но не копировать.
- Тела промптов и ответов модели. Хеши и метаданные — да, тела — нет: иначе коробка превращается в
  склад чужих данных.
- Дублирующие копии требований и ADR. Только id и путь.
