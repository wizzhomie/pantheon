# Sample reports

`sample_baseline.*`, `sample_guarded.*` and `sample_diff.md` are generated by `make sample`
from [`examples/logistics_intake/demo.py`](../examples/logistics_intake/demo.py).

**These are stub runs: no model was called.** The demo agent replays each golden answer with
one scripted defect, so the reports show how the loop, the checks and the metrics behave —
not how a model performs. Every file starts with that label, and the agent is recorded as
`demo-stub` rather than under a real model name, so a reader who opens one file cannot
mistake it for a measurement.

What the pair is meant to show:

| | baseline | guarded |
|---|---|---|
| Pass, final | 75.0% | 93.8% |
| False pass rate | 25.0% | 3.1% |
| Retry recovery | — | 88.9% |
| Escalation rate | 0.0% | 6.2% |

- **False passes** are the point: 8 of 32 answers were accepted in `baseline` mode and are
  wrong against the golden values. The gate flags 7 of them: 6 are fixed by one retry and
  `ed-04` never converges and escalates. The eighth is `adv-01`.
- **First-attempt pass rate dips** (75.0% → 65.6%) because the gate also returns two
  *correct* answers for repair: an unsupported citation and a duplicated cargo line. Quality
  is measured by `pass, final`; the first-attempt number is the price of the gate being on.
- **One false pass remains**: `adv-01` invents a weight of 800 kg. No deterministic check
  knows the email did not state it — only the trap in the golden data does, and the judge is
  off in this run. That case is the argument for the judge and for traps, not an accident.
- **Costs are $0.0000** because the stub reports no tokens. A live run fills them; see
  `make eval`.

Regenerate with `make sample` (deterministic, no key needed). The generated files are
committed so the README can link to them; replace them only with another stub run, and use
`make eval` + `make baseline` + `make diff` for the real numbers.
