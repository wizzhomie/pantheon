# Что ревьюер обязан знать об этом репозитории

Это проектный контекст (ADR-002): файл лежит в репозитории, ревьюится как код и
подставляется в промпт ревьюера. Здесь только правила, которые нельзя вывести из дифа.

- Публичные контракты — pydantic `StrictModel`: frozen, `extra="forbid"`, без полей «на всякий
  случай». Новое поле контракта — это новое обещание в отчёте.
- Команды проекта — argv-списки. Никакого `shell=True`, никакой строки с `;` в одном элементе.
- Вердикт считает код. Модель предлагает находки, но не может выставить PASS или убрать
  обязательный гейт.
- Документация не обещает того, чего нет: если функция не написана, README говорит об этом
  прямо.
- Тест на каждое новое поведение; исключение — когда тест невозможен, и тогда это написано.
- Секреты не попадают в артефакты и отчёты. Окружение дочерней проверки — белый список.

Правила ревьюера по существу: дефект, риск и пробел в тестах — единственные три вида находок;
стиль, нейминг и форматирование — не находки.
